# Deploying: Render (API) + Vercel (UI) + MongoDB Atlas

Free-tier setup for a public demo:

| Piece | Host | Plan |
| --- | --- | --- |
| FastAPI backend (Docker) | Render | Free: 512 MB RAM, sleeps after 15 min idle |
| React UI (static) | Vercel | Hobby |
| Conversations, chunks, eval runs | MongoDB Atlas | M0 (free) |
| Vectors | Pinecone | your existing serverless index |
| LLM | Groq | your existing key |

The live site runs in **public demo mode**:

* Anyone can **ask questions**. Requests are rate limited to 10 per minute per
  visitor and 25 per minute in total, so the demo can't drain the Groq quota.
* Visitors can browse the corpus and past evaluation runs.
* **Upload, seed, delete, running evaluations and query history need the
  admin key** (`RAG_API_KEY`). The key is never put in the frontend, because
  anything in a `REACT_APP_*` variable is readable by every visitor. You run
  admin actions with `curl`, or from a local UI that has the key.

Why the backend fits in 512 MB: embeddings run on fastembed's ONNX build of
MiniLM (no PyTorch), and RAGAS is only imported when an evaluation runs. The
API idles at about 280 MB.

---

## 1. MongoDB Atlas

1. Create a free **M0** cluster at <https://cloud.mongodb.com>.
2. **Database Access** → add a database user with a long generated password.
3. **Network Access** → add `0.0.0.0/0`. Render's free tier has no fixed
   outbound IP, so the strong password is what protects the database.
4. **Connect → Drivers** → copy the `mongodb+srv://…` string and put the
   password in it. This is `MONGO_URL`.

## 2. Backend on Render

1. Push this repo to GitHub.
2. In Render, go to **New → Blueprint**, pick the repo, and Render reads
   [`render.yaml`](render.yaml).
3. Fill in the secrets it asks for:

   | Key | Value |
   | --- | --- |
   | `GROQ_API_KEY` | your Groq key |
   | `PINECONE_API_KEY` | your Pinecone key |
   | `MONGO_URL` | the Atlas string from step 1 |
   | `CORS_ORIGINS` | `https://placeholder.invalid` for now; set it in step 4 |
   | `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` | optional; leave blank to turn tracing off |

   `RAG_API_KEY` is generated by Render.
4. Click **Apply**. The first build takes about 5 minutes. When it's done,
   check that `https://<service>.onrender.com/api/health` returns JSON.

## 3. Frontend on Vercel

1. In Vercel, go to **Add New → Project**, import the repo, and set **Root
   Directory** to `frontend`. Build settings come from
   [`frontend/vercel.json`](frontend/vercel.json).
2. Add one environment variable:
   `REACT_APP_BACKEND_URL = https://<service>.onrender.com` (no trailing
   slash). **Do not** add `REACT_APP_RAG_API_KEY`.
3. Click **Deploy** and note the URL, for example `https://rag-eval.vercel.app`.

## 4. Connect the two and seed the corpus

1. In Render, open the service → **Environment**, set
   `CORS_ORIGINS=https://rag-eval.vercel.app` (your exact Vercel URL), and
   save. Render redeploys.
2. Copy `RAG_API_KEY` from the same page, then seed the sample corpus:

   ```bash
   export API=https://<service>.onrender.com
   export KEY=<RAG_API_KEY from Render>
   curl -fsS -X POST "$API/api/documents/seed" -H "X-API-Key: $KEY"
   ```

3. Open the Vercel URL and ask a question.

## Admin actions on the live site

```bash
# Upload a document
curl -fsS -X POST "$API/api/documents/upload" -H "X-API-Key: $KEY" -F file=@my-doc.pdf

# Delete a document
curl -fsS -X DELETE "$API/api/documents/my-doc.pdf" -H "X-API-Key: $KEY"

# Run a small evaluation in the background, then poll the job
curl -fsS -X POST "$API/api/evaluations/run" -H "X-API-Key: $KEY" \
  -H "Content-Type: application/json" -d '{"scope":"testset","limit":5,"background":true}'
curl -fsS "$API/api/evaluations/jobs/<job_id>" -H "X-API-Key: $KEY"
```

Finished runs appear on the public Eval Dashboard.

## Free-tier behaviour to know about

* **Cold starts.** Render's free service sleeps after 15 minutes without
  traffic. The first request after that takes about a minute while it wakes,
  then everything is fast again. The BM25 index is rebuilt from Atlas on
  startup, so nothing is lost.
* **Evaluations.** A full 45-question run makes a few hundred Groq calls,
  which can exceed Groq's free daily token limit. Run evaluations with a
  small `limit`, or set `EVAL_LLM_MODEL` to a cheaper judge model.
* **One instance.** The rate limiter and BM25 index live in process memory.
  That's correct for a single instance; scaling out would need Redis for the
  limiter and a shared keyword index.

## Rotating secrets

Change the value in Render → Environment, and Render redeploys. To rotate the
admin key, edit `RAG_API_KEY` there; nothing in the frontend has to change.
